# pew2

Mobile remote control for **desktop coding agents** (Claude Code, Codex, Gemini CLI, GG Coder). The agent runs on the user's machine over the [Agent Client Protocol](https://agentclientprotocol.com); the phone is a client that watches the same session, prompts it, and answers its permission requests. **Transport + UI, not an agent.**

- `packages/protocol` — Zod schemas for provider manifests + the daemon↔relay↔app envelope, and the E2E crypto. Authoritative for both sides; `schemas/*.json` is autocomplete only, synced by hand.
- `packages/daemon` — spawns agents, speaks ACP over stdio, owns the seq'd session log, warm spares, probe cache, prefs, push, and the `pew2` CLI.
- `packages/relay` — Cloudflare Worker + Durable Object, one room per pairing; routes opaque sealed frames and stores nothing.
- `packages/app` — Expo/React Native client. `providers/*.json` — one manifest per agent; adding a file is the whole integration.

**Flow:** app `session.prompt` → relay → daemon → ACP `session/prompt`. Agent `session/update` → `SessionLog.append()` stamps a gapless `seq` → broadcast to **all** clients. ACP is one-client-to-one-agent; a phone and a desktop share a session only because the daemon owns the log, and reconnecting clients replay from a cursor because **ACP never re-sends**. Do not "simplify" that away.

## Gotchas — daemon

- **Register the permission resolver *before* notifying the UI** (`acp/connect.ts`) — a synchronous answer finds no pending entry and the agent hangs ("tap Approve, nothing happens"). The mirror rule: `close()` resolves every still-pending entry with `null`, which the request handler answers as ACP `cancelled`. An unresolved resolver keeps the whole connection closure alive for the life of the process.
- **Every session close goes through `closeSession()`** (`index.ts`) — the reaper, the `MAX_LIVE_SESSIONS` cap, a disabled provider and `closeAll` all used to do their own subset, and only shutdown discarded the attachment files, so every photo sent to a later-reaped conversation stayed in the tempdir for the daemon's lifetime.
- **A session blocked on an unanswered permission is reaped after an hour** — `working` is true for the whole wait, so the idle reaper never saw it and one unnoticed request pinned an agent plus a live slot for ever. Closing is not answering: nothing times a permission out (the phone can still answer for that hour), and the *whole session* goes, which the app already survives via `activeSessions` + `needsResume()`. The gate is `permissions.size > 0`, so a long working turn is untouched, and `lastUsedAt` is re-stamped when the request is registered so the clock starts at the question.
- **Spawned children need `error` *and* `spawn` listeners** — an unresolvable command emits `error` async, and unhandled it kills the daemon and every other session.
- **The useful half of an agent failure is JSON-RPC `data.details`** (sometimes double-encoded), and it arrives twice: as message text, then a rejection. `humanError()` (`errors.ts`) normalises at the one point all transports share. A clean exit is not an error — closing a session always fires `kind: "exit"`.
- **`resolveWorkspace()` (`workspace.ts`) is the only cwd default** (explicit → `PEW2_WORKSPACE` → daemon cwd → home). Under launchd cwd is `/` and agents treat cwd as project root — GG Coder died on `mkdir '/.gg'`. Session start *and* the capability probe go through it; a third spawn path reintroduces the bug.
- **A client's `cwd` is honoured only via `knownProject()`, and that check has to outlive the process** — the app re-sends its chosen project on every reconnect and every new conversation, for days. Browsed paths lived in memory alone, so a daemon restart made a genuine pick unknown, and both readers failed *silently*: `workspace.status` answered with the agent's previous project (the composer named a repo the user never picked) and `session.start` then refused the same path. Acceptance is written to `known-projects.json`, and the check reads the probe cache when no probe has landed yet — the app asks in the same breath as the probe it triggers, so recognition must never be a race against a spawn. `session.resume` still falls back rather than refusing (it arrives before the probe), but it may not *guess a project*: it takes the cwd the agent recorded for that conversation, because dropping to the provider's last workspace reopened a chat about one repo with the agent rooted in another.
- **Two prefs files, deliberately.** `config-prefs.json` (one file for all providers — read-modify-write it) seeds the *next new* session; `session-prefs.json` is replayed on `session/load`, because ACP resumes a transcript but hands back the agent's *default* selectors. Never apply the provider pref to a resume — that rewrites a desk-started conversation to match the phone's last pick.
- **Session ids die with the daemon; the app's list does not.** `needsResume()` (`agentHistory.ts`) is the single rule for opening a conversation, and an undefined `activeSessions` (older daemon) means *assume live*. Without it a restarted daemon answers `Unknown session '<id>'`.
- **Projects fold from the *uncapped* session list**, before `SESSION_HISTORY_LIMIT` (`projects.ts`) — the capped list is a recent-work window, so grouping it hides every repo not touched this week. Message counts hydrate per project on demand, never at probe time.
- **Worktrees are detected from git's own files, never by spawning git** (`worktree.ts`). ezcoder runs every task in `~/.ezcoder/worktrees/<repo>/ez-<id>`. Without detection, each of these looks like an unrelated project named after a random id, both in the drawer and to voice. `annotateWorktrees` runs once in `listSessions`, so the probe cache carries the result. It skips macOS-guarded folders (Documents, Desktop, `/Volumes`…), because the probe touches every project unprompted. `workspaceStatus` opts back in, since git already ran there. A *deleted* ezcoder checkout has no `.git` left, so it is recognised from the `~/.ezcoder/worktrees/<repo>/<name>` layout (`gone: true`) and linked to its main checkout by name only when exactly one project has that name (`linkWorktreeRoots`). `name`/`folder` stay the folder name, because session folder stamps are matched against them. **The wire stays flat; the app groups** (`groupProjects`, `projects.ts`). That gives one project per repository, with worktrees as `branches`, and `paths` for membership, so select and filter with `projectFor`/`projectContains`, never `===`. The same function is the duplicate check: one entry per path spelling, and same-titled projects or branches named apart. The daemon accepts an announced `worktree.root` in `knownProject` (it published that string), and `sessionsForProject(root)` includes the worktrees' sessions. In voice, a worktree is named `repo (branch)`, deleted ones are dropped, and its main checkout is added beside it. `list_projects` nests branches under each repo (`groupByRepo`), the repo's plain name scores worktrees at 0.9 so the main checkout wins, and tasks carry `repo`, stamped on every event they emit. **Reports name the repository, not the checkout**: push titles, the model's context, tool results (`project` + `branch`), the app's spoken note and banners all go through one `place` helper per side (`voice/place.ts` in daemon and app), so a branch finishing reads "black-mountain-fund · fix/login: finished". Tasks saved before `repo` existed are filed at startup from their own `cwd` (`backfillRepos`), because a deleted checkout is no longer in the registry. `projectIdFor` hashes the path without a trailing separator, so one directory never holds two ids.
- **The probe cache is stale-while-revalidate, not permanent** (`PROBE_TTL_MS`, `index.ts`) — it was memoised for the daemon's lifetime and refreshed once, on the first cache hit after boot, so every session and project started at the desk over the following days was invisible to the phone until a restart. A refresh must run *beside* the cached entry (never clear `probes` up front, or readers block on the reprobe and get nothing when it fails) and must not be delegated to `warmProvider`, which returns early whenever a spare is parked.
- **Warm spares: check `spares.has(id)` before booting, and gate readiness on `spareReady`, not `warming`** — a disk-cached probe skips the boot path, so the wrong flag duplicates an agent or blocks on a history read.
- **Conversations started at the computer are watched from the agents' own transcript files** (`desktop-activity/`, frame `desktop.activity`). The daemon never held them, so `busy` can't light their live mark. The watcher tails `~/.claude/projects`, `~/.gg`/`~/.ezcoder` `sessions` and `~/.codex/sessions`, and the app sets `deskBusy`, never `busy`, so it can't fight the turn machinery. Three rules apply. Sessions the daemon owns are excluded by `agentSessionId`, because its own ACP children write the same files. `working` expires 15 minutes after the last write, because a crashed CLI leaves a run that never finishes. It starts only from `server.ts` (`startDesktopActivity`), never `attach()`, so a test that builds a Daemon never reads the real home directory. `PEW2_DESKTOP_ACTIVITY=off` disables it. Prompt and reply text stay in the daemon, and voice gets them only through `peek_session`'s `speakable()`.
- **Two transports, one handler.** `handler.ts` owns every message case; `server.ts` (LAN) and `relay-client.ts` (remote) only supply `reply`/`broadcast`. A case added to one makes local and remote drift.
- **Relay: `ctx.acceptWebSocket()`, never `server.accept()`** — only that permits Hibernation, and the auto-response must match the daemon's exact `{"t":"ping"}`. It **requires `deviceId` on `/connect`** (400 otherwise) and **must forward `hello`, not answer it** — that is the daemon's only signal an app joined. A daemon socket is evicted only after it stops answering keepalives; "newest wins" let a stranger hold the machine offline.
- **The relay is untrusted by design.** Room id is derived one-way from the pairing token, frames are sealed per-message, the daemon won't start without a key, `PEW2_TOKEN` is refused below 32 chars (that string *is* the entropy), and a client `cwd` is honoured only via `knownProject()`. `/health` stays open so `doctor` separates "not running" from "unpaired".
- **Images are answered as a `reply`, never a session event** (`images.ts`) — in the seq'd log they'd re-download on every reconnect. The path comes from the agent, so it is realpath'd (macOS `/tmp` is a symlink) and confined to session cwd + tempdir. The 8MB ceiling exists because base64 inflates by a third, keeping a frame under the Durable Object's 32 MiB receive limit.
- **Attachments go the other way and land in tempdir, never cwd** (`attachments.ts`) — cwd is a git repo whose uncommitted count is on screen, and `git add .` would commit them.
- **Prompt blocks come from `promptCapabilities`** (`acp/promptBlocks.ts`) — an unadvertised block is a protocol error. A `resource_link` is advisory, so anything sent as a link is **also named by path in the text block**, or attaching to a non-vision agent silently does nothing.

- **Voice is two layers on one call** (`voice/`). The *call* is `VoiceController` (`controller.ts`): sign-in and credentials, the inbox, ring policy, threads, the board, minting, and the tools in `session.ts`/`tools.ts`. *Voice tasks* are `VoiceService` (`service.ts`, reached as `Daemon.voiceTasks()`): orchestrated tasks, goal runs, DAVE, focus and the check-in, with the tools in `taskTools.ts`. `voice.session` asks `VoiceService.brief(callId)` for the task half of the instructions and tools, and `buildSessionConfig` offers both sets. `voice.tool` sends a name `isTaskTool` accepts to `VoiceService.tool`, everything else to the call's own. `voice.end` ends both halves. Task news reaches a call in progress as `voice.note` through `VoiceController.noteCall`, and only while `callInProgress` (the board's call, not stale), so a call whose end never arrived stops hearing news and stops enabling auto-approval. Tools the call layer owns are not offered twice: approvals and questions are `list_waiting`/`answer_permission`/`answer_question` for every session, voice tasks' included, and hanging up is `end_call`.
- **Voice tasks: the daemon owns the state, the model is disposable.** Task tool calls are journaled to disk *before* they run, keyed by the Realtime function-call id (`toolCallId`); a retry returns the stored answer and a call caught by a crash answers "outcome unknown" — never re-run. Event ids come from the persisted store and must stay gapless.
- **Voice: "completed" is the agent's claim.** Only `verify_task` makes `verified`; a task running at restart becomes `failed` + `interrupted`. Nothing in `voice/` may report success on its own authority.
- **Voice approvals are checked against the live `requestId`**, and merge/deploy/destructive need a single-use `confirmToken`. An answer given in the app's own sheet goes through `Daemon.answerPermission`, which tells the orchestrator so the task leaves `blocked`; the voice path uses `answerPermissionQuietly` to avoid a double event.
- **Voice screenshots are ids, never paths or pixels, to the model** (`voice/screenshots.ts`, `request_screenshot`/`list_screenshots`/`attach_screenshot`). The phone uploads once (`voice.attach`, raster images only, checked by magic bytes, under `MAX_ATTACHMENT_BYTES`), the file lives in `<dataDir>/voice-attachments` (owner-only, never a project dir), and the store records it plus `sentTo`. A task carries `pendingAttachmentIds` until its prompt goes out, then `attachmentIds`; the bytes go through `Daemon.prompt`, so block choice stays `promptBlocks.ts`'s. Files are read *before* the prompt is sent: a missing one fails the turn ("attach it again") rather than sending an instruction about a picture the agent never got. Pruning skips anything a live task still has to send. The Tasks screen's "Send to agent" sends `voice.send`, which runs the same `attach_screenshot` tool through the executor, so both paths share the journal and checks. There is no `request_screenshot`: a call cannot open the phone's picker, so screenshots are shared from the Tasks screen.
- **Everything given to the voice model passes `speakable()`/`redactSecrets()`, and the model never supplies a `cwd`** — projects resolve through the registry (ambiguous means ask).
- **Voice consults DAVE (`~/dave`, the portfolio assistant) only when the user asks, apart from one read for the opening check-in** (`voice/dave.ts`, `check_backlog`/`delegate_backlog_item`). "Backlog" is the canonical word for the to-do list DAVE keeps, and the tools are named for it, never "dave", because `~/dave` is also a project. Their old names (`check_with_dave`/`delegate_dave_task`) are still accepted (`LEGACY_BACKLOG_TOOL_NAMES`) for a session minted before the rename, but they are never offered. The only unprompted contact is one GET of `/api/intel/focus` in `brief()` for the check-in (`daveDigest`): bounded to 1.5 s twice over (its own timeout and `withTimeout`), project names only (never objective text), silent on any failure, and `PEW2_DAVE_CHECKIN=off` turns it off without removing the tools. Nothing else touches it: not `contextText`, ticks, debriefs or notes (`service.test.ts` proves `brief()` makes exactly that one request, and none when opted out). Access is loopback-only (`PEW2_DAVE_URL` must be `http:` on 127.0.0.1/localhost/[::1], otherwise it fails closed) and sends DAVE's exact `Origin` because its guard requires one. Reads are GETs (`check_backlog` about next/progress/review read `/api/intel/next` and `/api/intel/briefing?caller=pew`; DAVE keeps the "since you last asked" cursor, Pew2 holds none). The only writes are confirm-gated changes to DAVE's own records: `DaveClient.post` allows only `/api/triage/{preview,apply,undo}`, `/api/intel/next/<16hex>/act` and `/api/intel/recommendations/suggestions/apply`, with DAVE's CSRF token (cached per client, refetched once on 403). `act_on_backlog` (`dave-act:<id>:<choice>`), `clean_up_backlog` (`dave-clean:<sha256 of sorted keys>:<action>`, applies exactly the previewed keys) and `undo_backlog_clean_up` (`dave-undo:<batchId>`) each need a spoken yes; `act_on_backlog` refuses hand-offs and never enqueues. `PEW2_DAVE=off` removes the tools. DAVE holds client and meeting data, so the model gets summaries through `speakable()` and never quotes, emails, links or provenance. Delegation always takes a confirm token (`dave:<objectiveId>:<projectId>`), refuses human-only steps, and only ever launches `ezcoder` with no fallback. DAVE itself never starts anything. **DAVE the assistant is not `~/dave` the project**, which is in the registry too. Every project-taking tool runs its words through `routeDave` (`voice/daveIntent.ts`). "Check the backlog" and "checking Dave, what's next on my to-do list" come back `meantBacklog` and start nothing. "Open the dave project", "work on dave", "the dave repo", "in dave" or a projectId mean the project. A bare "dave" with a to-do question asks which. A spoken *project* that is itself the backlog ("the backlog") always means the backlog unless it names a repo ("the backlog repo"). Every other rule fires only when the spoken project mentions Dave or resolved to dave, so a colleague named Dave, or "check the backlog", in another repo's instruction is left alone.
- **EZ Coder has two goal systems, and they are not interchangeable.** *EZ Goals* (the coordinator) live in `~/.ezcoder/goals/<slug>/goal.json`, run with the goal folder as cwd, and speak the same ACP `_gg/goals/*` contract as GG Goals. *Goal runs* (`/goal` plus the agent's `goals` tool) live in `~/.ezcoder/goals/projects/<sha256(resolve(cwd))[0:16]>/goals.json` (`EZ_GOALS_BASE` overrides the base) and run in the repository itself. The app's goals drawer is EZ Goals. Voice uses goal runs, because they run in the repo, so the registry, worktrees, `/commit` and approvals all apply unchanged.
- **Goals backends are one table** (`GOALS_BACKENDS`, `daemon/types.ts`): `gg-goals` → ggcoder (`~/.gg/goals`), `ez-goals` → ezcoder (`~/.ezcoder/goals`, `PEW2_TEST_EZ_GOALS_ROOT` in tests). Use `isGoalsId()`/`goalsBackend()`, never `=== GG_GOALS_ID`. A goals provider is announced only while its agent is enabled, and that agent's probe hides its goal folders. `isGoalFolder(cwd, goalsId)` is per backend and **excludes `<root>/projects`**, which is the goal-runs store and has no `goal.json`. `session.start`/`resume` on a goals id require a folder of *that* backend (`not_a_goal` otherwise), so an old app can never open an ez goal under `gg-goals`. On the wire, `providerIds` absent means gg only (exactly an old app's frame), `broadcastGoals(goalsId)` sends one backend with `providerIds: [goalsId]`, and the app's `applyGoalMessage` replaces only the backends a frame names. Goal ids are slugs and can collide across backends; `providerId` disambiguates.
- **Voice: a goal's progress is not a turn finishing** (`voice/goalRuns.ts`, `goalTools.ts`, `dispatcher.ts`). Runs are read from disk only, through a lenient schema where a malformed run is dropped, never thrown; every string passes `speakable()`, because the file holds absolute paths. In ACP mode ezcoder does not run its own goal loop, so the dispatcher sends "continue goal run" turns that ask ezcoder's `goals` tool `resume` for the next step, which keeps ezcoder the authority. After each turn `goalHooks.afterTurn` decides from the file. `complete` happens only once the run's status is `passed`, and that is still the agent's claim (`verify_task` makes `verified`). Otherwise the outcomes are needs-you (`blocked`), failed, stalled (`updatedAt` did not move across a continue, so `blocked`), or continue. Four rules bound the cost: at most `MAX_GOAL_CONTINUES` (6) continues before it blocks with "keep going?" (`follow_up` resets the count); the task state is re-read after every await, so a pause, cancel or timeout sends nothing more; a goal task running at restart becomes `failed` + `interrupted` and never auto-continues; and `start_goal`/`resume_goal` always take a confirm token and only ever use `ezcoder`. `GoalTracker` (from `tick()` and `brief()`) stats `goals.json` per live goal task and emits only `task.progress`, because the task's state has not changed, and the urgent announcement belongs to the transition `afterTurn` makes; announcing both rang the phone twice. An agent's `ask_user` becomes `task.question` + `blocked`; `answer_question` is stale-checked against the live `requestId`, like approvals.
- **Voice references resolve through recorded focus, never the model's memory** (`voice/focus.ts`, `resolve_reference`). Every successful tool call and every result or question event records typed refs (project, task, goal, result, question) in the store's `focus`, so they survive a new call and a restart. Each kind has its own half-life, the newest wins ties, and a `corrects` ref overrides. "That", "the agent", "the other project" and "yesterday's issue" resolve to ids, and anything without one confident match asks "did you mean A or B?". `follow_up`, `task_status`, `goal_status` and `answer_question` may omit `taskId` when focus resolves exactly one task, and the result says `resolvedFrom: "conversation"`; cancel, approve and commit still need an id or a confirmation. The clock and timezone are injected, so it stays deterministic. At most five "Working memory:" lines reach the instructions, with ids only in brackets.
- **A call opens with one deterministic check-in sentence, or none** (`voice/checkin.ts`, `VoiceService.checkin`). It counts tasks that finished or failed since `max(heardEventId, checkin.eventId)`, approvals and questions open now (live state, not events), goals needing the user, goal milestones and passes, sessions not owned by a voice task that are in `needs_you`, and DAVE projects whose top pick changed. Tool chatter is ignored. The first sight of DAVE records silently. The `Check-in:` line rides in the task half of the instructions, and the call's greeting uses it only when nothing is waiting. What a check-in covered, and every task event the call was told, is saved at `callEnded()`, never at `brief()`, so a call that failed to start repeats nothing and loses nothing.

## Gotchas — app

- **The composer is never disabled by the network** (`App.tsx`) — a phone is offline routinely, and locking the input was locking the user out of writing anything down at all. A send with no socket is queued in `outbox.ts` and delivered on reconnect; only `daemon.fatal` (rotated key, version mismatch) locks it, because nothing typed there could ever go. Queue rules: a start and its first prompt are queued **together or not at all** (a lone request opens an empty conversation), a second message joins the start already waiting rather than opening its own thread, only **one** `session.start` is in flight at a time (`pendingStart` holds one id), and `session.started` re-addresses everything queued against the `pending:` key or a dead pre-restart id. `busy` and the turn clock start when the frame actually leaves the phone — never when it was typed, or the duration is a measure of the tunnel. Agents are *discovered*, so the list is cached (`providerCache.ts` → `preferences.ts`) or a cold start offline knows of no agent to address a new conversation to; it is applied only over an empty list, never written empty (that frame means "still probing"), and cleared on unpair.
- **Voice tasks have their own screen, and no call of their own** (`ui/useVoiceTasks.ts`, `ui/taskController.ts`, `ui/TasksSheet.tsx`). The hook takes every frame through `onFrame` beside `useVoice`'s and folds `voice.state`/`voice.event`/`voice.dismissed`/`voice.attachments`/`voice.attached`/`voice.sent` into `voice/voiceStore.ts`, persisting the cursor and sending `voice.sync` on reconnect. Tasks opens from home's top bar (a dot when one needs the user); its "Call Pew" places an ordinary call. `pew2://voice` (the "Talk to PEW2" App Intent, `plugins/withVoiceIntent.js`) places a call by the same path as a tapped voice push.
- **Desktop images are a byte-capped LRU, and both maps move together** (`imageCache.ts`, `useDaemon.ts`) — a `data:` URI retains ~21MB per full-size image and nothing evicted them. `requestedImages` is the fetch-dedup guard, so a uri dropped from `images` but left in it is a permanent spinner; `putImage` returns the evicted list precisely so both can be cleared, and eviction is computed *outside* the `setImages` updater because an updater may run twice. `ChatImage` re-requests whenever its entry is missing, which is what makes eviction cost a round trip instead of a blank cell.
- **Turn ids are `${sessionId}:${seq}`** — `seq` restarts per session, so seq alone collides and React merges unrelated turns.
- **Filter `session.event` against `sessionRef.current`; `session.idle` is deliberately *not* filtered** — it is the only signal a background conversation finished, so it applies per session and is never replayed.
- **Replay overlaps the live stream** — drop events at or below the per-session cursor (`cursors.ts`). A replay batch must never set `busy` or raise `permission` (`replayFold.ts`): perpetual spinner, phantom approve sheet. It *does* carry the last `usage_update`.
- **An open approval is state, not an event** — so a catch-up carries `permissions` beside `working`, because the logged `permission_request` is skipped as history and nothing times a permission out at either end (a phone that dropped signal mid-request left the agent stopped for ever). Absent means "an older daemon said nothing", `[]` means "none pending" and dismisses the sheet; the request is filed on the *session* row, so it survives switching conversations.
- **Chunk merging is decided by the *seam*, not the provider** (`chunkJoin.ts`) — some agents stream tokens, others send whole messages; whitespace either side means continue, a sentence ending against a capital gets `\n\n`, and a real char must precede the stop or `"3."`+`"14"` splits.
- **Map `user_message_chunk`, not just live prompts** (`chunks.ts`) — GG Coder replays user turns that way. A turn is empty only with no text *and* no images (tool-generated images have no chunk).
- **Context % comes from optional ACP `usage_update`** — an agent that sends none gets **no reading, not 0%**; the window is per model, so readings don't compare across a switch.
- **The transcript is FlashList v2 and owns its scroll** (`ui/ChatThread.tsx`): `maintainVisibleContentPosition` + `startRenderingFromBottom` is the whole mechanism. Never scroll imperatively from `onLayout`/`onContentSizeChange`; the `threadBottom` catch-up is grow-only and unanimated (the dock resizes around the keyboard, and two curves = the thread re-seating). Cells recycle, so a mount is not a new message.
- **`@pew2/protocol` imports work only because `metro.config.js` maps the `.js` suffix back to `.ts`.** If a bundle dies on "Unable to resolve", suspect that shim first.
- **Pure modules stay Expo-free** (`pairingLink.ts`, `hapticsPolicy.ts`, `notificationPolicy.ts`, `transcription.ts`, `permissions.ts`); native binding lives in the `ui/` twin. Importing `expo-*` into the pure half breaks `bun test`, which cannot parse React Native's Flow syntax.

## Workflows

- **`npm run daemon` is not the server** — it prints JSON and exits. The WebSocket server the app talks to is `bun run packages/daemon/src/server.ts` (8787, `PEW2_PORT`). The `echo` provider is a real ACP agent needing no key or network — the only offline way to exercise the pipeline.
- **Live loop:** start that server, then `cd packages/app && npx expo run:ios`, scan the printed QR. **Expo Go can no longer load this app** (keyboard-controller, glass, picker, speech are native). After `npx expo install`, **restart Metro** — a stale graph reads as a module missing at runtime.
- **A `Sheet`-based harness renders blank on `expo start --web`** — `WorkletsError: createSerializableObject should never be called in JSWorklets`, and it takes the whole tree with it (`NewChatSheet.harness`, `MessageSheet.harness`; `ChatThread.harness` is unaffected). Run those with `npx expo run:ios`, and relaunch between screenshots: fast refresh keeps state, so an edited fixture never moves and the card is caught mid-spring.
- **`pew2` is not on PATH until `cd packages/daemon && bun link`.**
- **Know which half you changed, because they ship on separate rails and neither carries the other.**
  - `packages/daemon`, `packages/protocol`, `providers/*.json` → **binary release**. Tag `v*`; `release.yml` cross-compiles, checksums, and publishes to `releases/latest`, which is the path `install.sh` / `install.ps1` resolve by name. Users re-run the curl line.
  - `packages/app` → **IPA**. `scripts/build-ipa.sh`, then Transporter and App Store review — days, not minutes, and the user cannot be told to hurry.
  - `packages/relay` → `npm run relay:deploy`. Ships instantly and independently of both, since it only routes sealed frames.
  - The manifests are **compiled into the binary**, not read from disk (`release.yml` verifies the count), so adding a provider is a daemon release even though it is only JSON.
- **A wire change is both, and the daemon is the half that has to tolerate the gap.** Nothing negotiates a version: the app is on the App Store's clock while the daemon updates the same day, so every new field is optional on arrival and absent means "older peer", never "none" — the reason `activeSessions`, `permissions`, `projects` and `commands` all distinguish absent from empty. Ask "does an old app talking to this daemon still work, and an old daemon to this app?" before assuming a change is daemon-only.
- **A daemon-only fix still needs the running process restarted.** Development runs from source (`bun run packages/daemon/src/server.ts`), so an edit changes nothing until that process is killed — a long-lived daemon holding stale in-memory state is exactly the class of bug that hides here.
- **`bunfig.toml` preloads `scripts/test-setup.ts`, which gives each run its own `TMPDIR`.** Tests `mkdtemp` constantly and essentially never clean up — 27,645 directories and 257MB had accumulated — so the run is retargeted at one root and swept in `afterAll`. Not `process.on("exit")`: the test runner ends the process without running exit hooks. A test that asserts a literal system temp path will fail here, and that is the fix, not the path.
- **`children.ts` handles SIGINT/SIGTERM/SIGHUP only when nothing else does** — a default-disposition signal runs no `exit` hook, so Ctrl-C on the CLI or on a `bun test` run orphaned its agents to pid 1. The handler bails when `process.listenerCount(signal) > 1` (that is `server.ts`'s graceful shutdown, which wants its 500ms grace) and otherwise kills owned children, removes itself and re-raises — without the re-raise, importing this module would make a process survive its own Ctrl-C.
- **Keep `npm test`'s explicit source roots.** `bun test packages` walks 13k dirs, blows past Darwin's OPEN_MAX, and spawned children then read back empty with exit 0 (Bun #32067) — correct code, red tests. Add a root when a new package gets tests.
- **Two checks need a server already running and are not in `npm test`:** `npm run relay:dev` then `npm run relay:check`; and, with the daemon up, `bun run packages/daemon/src/testing/e2e-check.mjs`. `wrangler dev --local` silently breaks WebSocket upgrades, so `relay:dev` does not pass it.
- **`providers validate` only proves the JSON parses; `providers verify <id>` spawns and prompts the agent** — always finish with `verify`.
- **The Android CI job is the only native-config check** — `ios/` and `android/` are gitignored, so a plugin collision or autolink failure is invisible to typecheck/test. iOS is verified locally (`expo prebuild --platform ios` + `pod install`); macOS runners bill 10x.
- **iOS config traps** (`app.json`): two plugins must never claim one Info.plist key (the later silently wins — `expo-camera` owns `NSCameraUsageDescription`, `expo-media-library` owns `NSPhotoLibraryUsageDescription`, so `expo-image-picker` declares neither); `ios.infoPlist` ships verbatim, so no `"//"` comment keys; `ITSAppUsesNonExemptEncryption: false` or every EAS build stops for a manual answer.
- **The EAS iOS build image is pinned** (`eas.json`) — Xcode 26.0 desyncs `react-native-keyboard-controller`'s per-frame numbers, since UIKit gates on the SDK built against. Never `auto`/`latest`; if the keyboard is off again, suspect this line first.
- **Shipping an `.ipa` is `packages/app/scripts/build-ipa.sh`** — `eas build --local` runs the same pipeline on this Mac in ~3 min and costs no build credits, where the cloud build is metered and queues. It leaves one `pew2-build<N>.ipa` on the Desktop for Transporter, deletes the previous one *after* a successful build, and refuses to hand over anything signed `get-task-allow=true` (a development profile uploads fine, then gets rejected by email hours later). Still needs an Expo login even offline of the cloud builder: `appVersionSource: remote` means the build number is incremented server-side, so an anonymous run dies after installing pods. `release-to-device.sh` is the other half — dev-signed, for reproducing Release behaviour on a plugged-in phone, never uploadable.
- **No Expo account is committed** (`app.config.js`) — identity layers in from `EAS_OWNER`/`EAS_PROJECT_ID` or a gitignored `eas-project.json`, so push degrades to local-only banners on a fresh clone instead of breaking.
- **Self-update is a swap plus an exit, and the exit is the dangerous half** (`update/`). `check.ts` reads the latest release tag, `apply.ts` downloads it, verifies the published `.sha256` and *renames* it over `process.execPath`, `scheduler.ts` exits so a supervisor relaunches on the new inode. Three rules: the staging file is written **beside the target** (rename is only atomic within one filesystem, and `os.tmpdir()` is routinely another volume); it exits **only when `daemon.busyReason()` is undefined** (never mid-turn, never with a permission on screen); and it refuses unless `isCompiled()` — under `bun run`, `process.execPath` is the developer's **`bun`** binary, and a rename would replace the runtime every other project on that machine depends on.
- **A supervisor is what makes exit-to-update legal, and it is per-machine, not per-platform** (`cli/service*.ts`). All three have one — launchd `KeepAlive`, systemd `Restart=always`, and a Scheduled Task whose repeating trigger plus `IgnoreNew` policy is the same thing at one-minute granularity. Each must restart after a **clean** exit: `Restart=on-failure` and Task Scheduler's `RestartOnFailure` both ignore exit 0, which is exactly how the updater ends the daemon, so either would swap the binary and never come back. The gate is `supervisorInstalled()` — the service *file on disk*, not `process.platform`, because `pew2 serve` is a first-class command and a fresh install has no service until `pew2 setup` writes one. Windows additionally cannot unlink or replace a running `.exe`, only rename it, so the outgoing binary is parked aside and restored if the swap then fails. systemd needs `loginctl enable-linger` or the daemon dies at logout.
- **`pew2 setup --json` / `doctor --json` are the agent-facing surface** — `ok` is the stop condition, each problem carries a stable `id` and runnable `fix`, and missing secrets or LAN-only are `warning`, never `error`, so an agent can't loop on what it can't supply.
